## 3. Security review

| | Item | Status |
|---|---|---|
| 3.1 | Whole-codebase review (secrets, webhook auth, agent sandbox, scope isolation, SSRF, authorization, resource limits, file permissions, TLS) | ✅ 2026-10-14 |
| 3.2 | Findings fixed or recorded as known issues in the release notes | ✅ below |

Sound: no secret reaches logs, errors, agent text or saved documents (including Telegram file URLs);
Zalo and Telegram webhooks check their secrets in constant time, with a 1 MiB body limit; Google Chat
JWTs are fully checked; agents run with tool allow-lists, a scrubbed environment and loopback-only
MCP with 256-bit tokens; scope isolation and path handling hold; pairing codes are rate-limited
and expire; `.env` is 0600; TLS goes through rustls with ring only.

Fixed on this branch:

| Severity | Finding | Fix |
|---|---|---|
| High | A turn batched messages from several people and ran them all with the last sender's identity and admin rights | a batch holds one author's messages only (`dispatch.rs`) |
| High | A routine's title (part of its unattended prompt) could be changed without pausing it, by anyone who could see it | only the owner or admins change a routine (others may pause it); a new title or new notes pause it |
| Medium | `/snooze` trusted any history line containing "(reminder `t-…`", so it could restart a paused routine | only the scheduler's own bot lines count, and routines cannot be snoozed |
| Low | Downloads buffered a body without `Content-Length` before checking the size | read in chunks with a running cap |
| Low | The Google Chat key was briefly world-readable; `state/` used the default umask | key created 0600; `state/` set to 0700 |
| Low | Slack and Google Chat links with a non-web URL (`[x](!channel)`) could ping everyone | only `http(s)`/`mailto` URLs become links |
| Low | `TELEGRAM_` variables were not in the default agent-environment scrub list | added (configured names were already removed) |
| Medium | In a group, the asker's personal profile was in the prompt and answers could reveal personal memory, tasks or notes to everyone there | in groups the scope has no personal folders (reads and writes refused) and no profile in the prompt; rooms can opt in with `personal = true`; a personal bot ignores non-owners in groups silently |

Known issues for the release notes (not blocking):

| Severity | Issue | Plan |
|---|---|---|
| Medium (plausible) | The `web` policy lets the agent CLI fetch any URL from the bot host, including private addresses and cloud metadata | document; recommend `mcp-only` for group rooms on cloud VMs; consider a fetch proxy later |
| Low | Google Chat: tokens with unknown key ids each force a key refetch, under a lock | throttle refreshes to one a minute |
| Low | The HTTP server has no header/read timeouts; `/metrics` and `/healthz` are public | run behind the documented reverse proxy |
| Low | Any group member can `/stop` or `/reset` the room's turn; `global` memory can be written by anyone (by design, D2) | document |
| Low | Telegram resolves file ids (`getFile`) before access rules drop a message | resolve lazily |
