# Release checklist — v0.14.0

A minor release: **apps** (ADR 0019, ADR 0020, `docs/design-apps.md`, phases P32–P36). Apps are
sandboxed web pages behind chat summaries, opened by the person who pressed the button through a
single-use launch ticket. Seven apps are built in, and more come from a signed registry
(`tidusvn05/okbot-apps`). It follows `docs/implementation-plan.md` Part 5 and
`docs/releasing.md`. Status as of 2026-11-27; ✅ done, ⏳ to do, ⚠️ done with a caveat.

## 3. Security review of the diff since v0.13.1

| | Item | Status |
|---|---|---|
| 3.1 | Review of `git diff v0.13.1..main` (tickets, sessions, App API, shell and SDK, CSP, registry, install paths, channel delivery) | ✅ 2026-11-26 |
| 3.2 | Findings fixed or listed as known issues | ✅ 4 Medium and 4 Low, all fixed in #87 (`docs/design-apps.md` §11) |

Fixed:
- `knowledge.get` reached memory and notes through `./memory/…`.
- A frame that navigated away kept the app's bridge.
- The `mcp.call` confirmation could be timed to catch a keystroke.
- An in-flight request could undo a sign-out.
- Login CSRF through someone else's link.
- Place numbers shifted after eight places.
- An old signed index could be replayed to downgrade apps.
- Room access outlived membership; rooms now drop out after 12 h.

Known and documented: an app can still carry data it was granted out of the browser by
navigating its frame (the shell then closes it). Registry review and narrow grants are the defence
(ADR 0019).
