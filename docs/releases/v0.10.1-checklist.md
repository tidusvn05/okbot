# Release checklist — v0.10.1

A patch release: fixes found running a team across two real machines (#48), the agent CLI path that
broke when Codex updated itself (#50), team manifests that no longer need renewing by hand every 90
days (#49), and a clearer installer error (#47). Nothing in `okbot.toml`, the bridge protocol or the
`okbot-core` API changes. It follows `docs/implementation-plan.md` Part 5 and `docs/releasing.md`.

## 3. Security review of the diff since v0.10.0

| | Item | Status |
|---|---|---|
| 3.1 | Review of `git diff v0.10.0..main` (relay routing, manifest validity and renewal, agent CLI search, release script, installer) | ✅ 2026-10-25 |
| 3.2 | Findings fixed or listed as known issues | ✅ none |

Sound: a relay's own `okbot chat` now reaches the running relay with a signed request, checked like
any other (`relayed_by_me`, `may_call`), still sealed; `renew` cannot skip a revocation (editing the
manifest deletes its signature); the agent CLI search covers only the service user's home and
root-owned directories, as `okbot init` already did, and the untrusted agent's own home is not
searched; new warnings print paths and day counts only.

Note (not blocking): on a shared macOS machine, `/usr/local/bin` and `/opt/homebrew/bin` belong to
whoever installed Homebrew; a bot without a pinned `cli` searches them too, as `okbot init` did.
