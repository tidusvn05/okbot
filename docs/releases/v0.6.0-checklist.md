## 3. Security review of the diff since v0.5.0

| | Item | Status |
|---|---|---|
| 3.1 | Review of `git diff v0.5.0..main` (secrets, signing, commands, scope isolation, MCP calls, rendering) | ✅ 2026-10-17 |
| 3.2 | Findings fixed or listed as known issues | ✅ below |

Sound: run tokens are HMAC-SHA256, compared in constant time, with an expiry, and checked with each
server's own key; callbacks must be on the server's own origin, and nothing in chat can set them; chat
cannot pick the server, the tool or the callback; commands pass the dispatch gate and `admins_only`;
form values are `Secret`, never logged and never shown to the agent or kept in the history; Discord
sends with no allowed mentions and no embeds; the `[[mcp]]` secret is in the log redactor; reqwest
uses rustls; MCP bodies are capped at 4 MiB; commands never read knowledge.

Fixed before the tag (#23):

| Severity | Finding | Fix |
|---|---|---|
| Medium | Chat could override a command's fixed `with` arguments (`/status company=other`), also through a Discord slash option value | `with` keys refused as `name=value`; an argument also in `with` is a config error; Discord quotes option values containing `=` |
| Medium | reqwest errors include the URL, so a failed MCP call put the `[[mcp]]` URL (internal host, any `?key=`) into chat and logs | `without_url()` on MCP and callback errors |
| Medium | `/interact` accepted any token signed with the server's key, so the server could mint tokens for any conversation | only tokens okbot issued (`jti` until `exp`) |

Known issues for the release notes (not blocking):

| Severity | Issue | Plan |
|---|---|---|
| Low | Error texts of tools and JSON-RPC errors go into the chat as they are | document; an option to show only "failed" |
| Low | A tool result up to 4 MiB is split into many chat messages; `/stop` probably cannot cancel a command | cap the chat text; a cancel token for command runs |
| Low | The prompt callback's reply is read without a size limit | read in chunks with a cap |
| Low | The Discord adapter never forgets closed prompts (memory grows with uptime) | remove them on close and expiry |
| Low (plausible) | `answer_by = "anyone"` means anyone when `allow_users` has no entry for the channel; answers skip the dispatch gate | treat it as nobody; check answers at the gate |
| Note | `[[mcp]]` gives the agent every tool of that server, and remote `http://` URLs are accepted | document: never point it at shell or file servers; warn on non-loopback `http://` |

Known issues carried over from v0.5.0: see `docs/releases/v0.5.0-checklist.md` §3 (the `web` policy
can reach private addresses; zip 8.x through anydoc).
