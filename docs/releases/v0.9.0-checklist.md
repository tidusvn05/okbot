# Release checklist — v0.9.0

The fifth release: the console channel stands in for real platforms when testing a bot. It
simulates users, group rooms and threads (`:as`, `:room`, `:thread`), copies platforms' limits
(`okbot chat --like`), and applies the bot's access rules (`--strict`). Scenarios can be checked
(`:expect`) and answered without an agent CLI (`--agent echo`, `--replies`), so they run as CI
tests. It follows `docs/implementation-plan.md` Part 5 and `docs/releasing.md`. Status as of
2026-10-21; ✅ done, ⏳ to do, ⚠️ done with a caveat.

## 3. Security review of the diff since v0.8.0

| | Item | Status |
|---|---|---|
| 3.1 | Review of `git diff v0.8.0..main` (console input and output, history file, scripted agent's MCP client, owner rule, `--strict`, `--http`, `deny.toml` targets) | ✅ 2026-10-21 |
| 3.2 | Findings fixed or listed as known issues | ✅ fixed before the release (#35) |

Fixed: `:press` form values were saved in the console history (Medium; such lines are no longer
saved); the history file was readable by other users (now 0600); bot output reached the terminal
with control characters (now escaped, as in `okbot history`).

Sound: the scripted agent is only selectable in `okbot chat`, never in `okbot.toml`; its MCP
errors leave out URLs; it uses the turn's token and gateway like any agent. Only the console user
from `--user` is the owner of a personal bot (`console_owner`); others need pairing. `--strict`
reads secrets as `okbot run` does. The console checks who may answer a prompt before it hands the
answer to the runtime.

Known issues for the release notes (not blocking):

| Severity | Issue | Plan |
|---|---|---|
| Note | `:as` in `--strict` lets the terminal write as any account, admins included | by design: the terminal is the operator |
| Note | `deny.toml` checks the released targets only (Linux, macOS); Windows-only dependencies are not checked | revisit if okbot ships for Windows |
| Note | `--http` binds where it is told; it serves `/notify` and `/interact`, both token-protected | documented: use a loopback address |

Known issues carried over: see `docs/releases/v0.8.0-checklist.md` §3.
