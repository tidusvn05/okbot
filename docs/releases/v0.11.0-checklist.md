# Release checklist — v0.11.0

The seventh release. Interactive replies: with `reply_mode = "interactive"` the agent can answer with
buttons, selects, forms and cards through the built-in `show` tool, and a click comes back as a new
chat turn (ADR 0015). Charts in those replies are drawn as PNG images by the new crate `okbot-chart`,
with fonts for Vietnamese, English and Japanese embedded (ADR 0016). The default reply mode is
unchanged. It follows `docs/implementation-plan.md` Part 5 and `docs/releasing.md`. Status as of
2026-10-27; ✅ done, ⏳ to do, ⚠️ done with a caveat.

## 3. Security review of the diff since v0.10.1

| | Item | Status |
|---|---|---|
| 3.1 | Review of `git diff v0.10.1..main` (interactions and views, the `show` tool, rendering on each platform, chart limits and rendering, uploads, console files, Discord permissions, gateway compression) | ✅ 2026-10-27 |
| 3.2 | Findings fixed or listed as known issues | ✅ fixed before the release (#56) |

Fixed (Medium): a press that dispatch would then drop (rate limit, input length, a non-owner on a
personal bot) used up the view before the checks; the checks now run first, counting nothing.
Discord and Slack kept every open prompt with its chart PNG for the life of the process; they now
keep prompts without pictures and forget them after 7 days.

Fixed (Low): 32-bit view ids and `INSERT OR REPLACE` (now 128-bit, never replaced); the restart
lookup ignored the room (now same channel and room); raw card titles in Slack's mrkdwn fallback;
the secret-field filter missed Japanese; console charts in a shared temp folder (now private, 0700);
display names as Markdown in outcome lines. Also `ui` is a reserved `[[mcp]]` name and pre-filled
form values respect the field's length.

Sound: answers only for the view's channel and room and its answering ids; one answer per view
(`DELETE … RETURNING`), expired views filtered and purged; a press is an ordinary message (`→`
prefix, no `/commands`, normal dispatch); automations and peer turns never get `show`; empty
`allowed_mentions` on Discord, escaping on Telegram and Google Chat, Slack headers as plain text;
link buttons `https` only; chart limits checked before drawing (NaN, size, counts); no URL with a
token in logs or chat errors; the runtime reaches charts only through `ChartRenderer`.

Note (not blocking): a chart render that passes its 2 s timeout keeps running in its blocking
thread until done; the work is bounded by the chart limits, and extra fonts come from the operator.
