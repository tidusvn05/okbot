# Release checklist — v0.10.0

The sixth release. Everyday services through OAuth MCP servers, connected by each person from chat
(ADR 0012); automations with polling, schedules and webhooks (ADR 0013); knowledge packs and the
`okbot-guide` pack; and teams of bots that delegate work to each other over A2A, on one machine or
several, with A2A agents and programs outside okbot (ADR 0014). It follows
`docs/implementation-plan.md` Part 5 and `docs/releasing.md`. Status as of 2026-10-24 (after the release); ✅ done,
⏳ to do, ⚠️ done with a caveat.

## 3. Security review of the diff since v0.9.0

| | Item | Status |
|---|---|---|
| 3.1 | Review of `git diff v0.9.0..main` in two parts: #44 (peers) and the rest (OAuth, connect, automations, interact `next`, packs, CLI) | ✅ 2026-10-24 |
| 3.2 | Findings fixed or listed as known issues | ✅ fixed before the release (#44) |

Fixed (High): a team member could name any person as the origin of a delegation, and the callee
used that name as the OAuth subject of `credentials = "person"` servers (peer turns counted as
direct chats), including a personal bot's owner. A delegated task now acts as its person only with
`[teams.<id>] act_as_person = true`, a person in the callee's `[people]`, and never on a personal
bot.

Sound (OAuth and automations): state and PKCE single-use with expiry; chat links finish with a
code bound to the conversation and subject, cut off after five wrong codes; sealed credentials bound
to kind, server and subject; no redirects followed; errors without URLs; HTML escaped on the callback
page; automation webhook tokens compared in constant time; `automation:` event ids cannot be forged
by any channel; restricted turns have no web, read-only bot tools and approval for every change.

Sound (peers): okp1 tokens checked against the manifest key before the replay cache; every task
operation bound to its signer; relay poll and reply only for the relayed member; sealing with fresh
ephemeral keys; manifest rollback refused; peer events never run commands or get `admins`;
external clients get their person and context from local configuration.

Known issues for the release notes (not blocking):

| Severity | Issue | Plan |
|---|---|---|
| Note | Approvals a callee asks for are answered through the calling bot; a dishonest caller could answer itself | documented (ADR 0014, `docs/peers.md` §4): trust every member's operator before `confirm` relies on it; a person-signed answer is future work |
| Note | Relays read nothing (sealed) but see who talks to whom and when | by design |
| Note | No RFC 8414 issuer check for OAuth mix-up across several authorization servers | hardening, later |

Known issues carried over: see `docs/releases/v0.9.0-checklist.md` §3.
