# Release checklist — v0.8.0

The fourth release: an MCP gateway for `[[mcp]]` servers with roles, rooms, tool lists, approvals,
audit, per-person limits and local stdio servers (ADR 0011); prompt buttons on Telegram, Slack and
Google Chat; and `okbot agent` and `okbot history` for operators. It follows
`docs/implementation-plan.md` Part 5 and `docs/releasing.md`. Status as of 2026-10-21;
✅ done, ⏳ to do, ⚠️ done with a caveat.

## 3. Security review of the diff since v0.7.0

| | Item | Status |
|---|---|---|
| 3.1 | Review of `git diff v0.7.0..main` (gateway tokens, permission checks, approvals, grants, stdio processes, history SQL, terminal output) | ✅ 2026-10-21 |
| 3.2 | Findings fixed or listed as known issues | ✅ fixed before the release (#31, #32) |

Fixed: an approval could show arguments cut at 800 characters while the full call was sent (Medium;
now the arguments are shown in full or the call is declined unasked); the gateway relayed methods
other than tools without checks (now only `initialize`, `ping`, notifications, `tools/list` and
`tools/call` with an id); an answer to an abandoned approval said "Allowed" (now "nothing was done",
and expired approvals close); chat text could carry terminal control sequences into `okbot history`
and `okbot audit` (now escaped); local server sessions per turn are capped at 8; tool annotations are
re-read after 10 minutes.

Sound: turn tokens are 32 random bytes kept as digests, end with the turn and never carry a server's
secret; permissions are checked on every call, not only when servers are offered; answers are checked
for room, button, person, expiry and forms; `/grant` needs an administrator and cannot give `admins`;
stdio servers get an empty environment; history SQL is parameterised and opened read-only.

Known issues for the release notes (not blocking):

| Severity | Issue | Plan |
|---|---|---|
| Note | Resources and prompts of `[[mcp]]` servers are not offered through the gateway | add rules for them when a user needs them |
| Note | Tool annotations decide what `confirm = "destructive"` asks about; they come from the operator's server | documented; `confirm = "always"` for servers not trusted to annotate |

Known issues carried over: see `docs/releases/v0.7.0-checklist.md` §3.
