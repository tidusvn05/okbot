## 3. Security review of the diff since v0.6.0

| | Item | Status |
|---|---|---|
| 3.1 | Review of `git diff v0.6.0..main` (tokens, target selection, error texts, history, dedupe state) | ✅ 2026-10-20 |
| 3.2 | Findings fixed or listed as known issues | ✅ no finding; notes below |

Sound: each `[[notify]]` token reaches only its own `to` list (callers cannot name chats); an unknown
name and a wrong token answer the same `401`, before the body is parsed; tokens are compared without an
early exit, kept in the log redactor and out of agent environments; a bearer `[[mcp]]` token (which the
agent receives) is refused as a notify token; adapter errors returned to callers carry no token (zalo-bot
and Telegram strip URLs); the dedupe map is bounded and only filled by authenticated requests; text is
capped at 8000 characters; history entries are marked as another program's information.

Known issues for the release notes (not blocking):

| Severity | Issue | Plan |
|---|---|---|
| Low | Platform error texts are returned to the caller as they are | they carry no secrets; an option to return only codes if needed |
| Low | Dedupe ids live in memory and are forgotten on restart | documented; callers needing exactly-once keep their own state |
| Note | `/notify` is served on `[http] listen`, which may be public for webhook channels | bearer token per target; document a random 32-byte token |

Known issues carried over from v0.6.0: see `docs/releases/v0.6.0-checklist.md` §3.
