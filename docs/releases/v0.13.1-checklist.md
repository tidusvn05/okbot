# Release checklist — v0.13.1

A patch release. okbase 0.2.7 brings anydoc 0.2.5 on zip 9, which closes every Dependabot alert on
zip 8.6.0 (1 critical, 3 high, 1 medium) and the new RUSTSEC-2026-0545..0548 that failed cargo-deny
(#83). `okbot chat` now uses `kb` and `state_dir` from `okbot.toml` (#76, #81), and `knowledge_add`
merges a frontmatter block in its text instead of writing a second one (#80, #82). It follows
`docs/implementation-plan.md` Part 5 and `docs/releasing.md`. Status as of 2026-11-21; ✅ done,
⏳ to do, ⚠️ done with a caveat.

## 3. Security review of the diff since v0.13.0

| | Item | Status |
|---|---|---|
| 3.1 | Review of `git diff v0.13.0..main` (`chat` path resolution, `knowledge_add` frontmatter merge, okbase/anydoc/zip update, `deny.toml`) | ✅ 2026-11-21 |
| 3.2 | Findings fixed or listed as known issues | ✅ one Low, fixed in #82 |

`knowledge_add` stays owner/admin only. An agent can now choose frontmatter keys of an inbox
document, so the review checked what reads them: tasks are read only under `tasks/` (an inbox
`type: Task` is ignored), and the only scope filter is `audience` not `private`, so a key can hide
the agent's own document but never widen visibility. `title`, `updated`, `source`, `added_by` and
`generated` are always okbot's. Low, fixed: an attached file was written before the frontmatter
merge, so a refused merge left a stray file in the inbox; it is now written after the document is
built. `okbot chat` only resolves paths the operator wrote in `okbot.toml`.
